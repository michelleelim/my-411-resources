## **Project Description:**

This project will develop CodeChuckle’s GiggleGit, a version control system where merges are managed by memes. The goal is to create an interactive onboarding experience that helps new users understand and use GiggleGit effectively and efficiently. 

**Project Requirements:**  
**Goal:** Increase engagement by providing an interactive experience for GiggleGit users

**Non-Goal:** Develop IOS features or any AI-powered solutions for merges

**Non-Functional Requirement 1:** User security and access control  
	**Functional Requirement 1:** Use role-based authentication

- Be able to differentiate between different groups of users (regulars, leads, etc.) and allow different levels of access for each respective group

	**Functional Requirement 2:** Limit access when editing content

- Only admins/PMs should be able to create, edit, or delete any snickering content

**Non-Functional Requirement 2:** Randomization   
	**Functional Requirement 1:** Implement user assignments

- With a randomized algorithm, users should receive  automatic assignments used for forming or controlling groups

	**Functional Requirement 2:** Keep track of user assignments 

- User group assignments should be recorded to avoid any unsecure logistical actions or analysis 

**Agile:**  
**Theme:** Get GiggleGit demo into a stable enough alpha to start onboarding some adventurous clients 

**Epic:** Onboarding experience 

**User Story 1:** As a vanilla Git power-user that has never seen GiggleGit before, I want to quickly understand the difference between Git and GiggleGit so I can use it effectively without interrupting my workflow.   
**Task 1:** Create a clear onboarding tutorial for new users   
**Ticket 1:** Create onboarding tutorial  

- Make a documentation presenting what should be covered (merge handling with memes, commands, etc.) 

**Ticket 2:** Implement UI for tutorial 

- Create the front end components with clear tutorial instructions for effective user engagement

**User Story 2:** As a team lead onboarding an experienced GiggleGit user, I want to have a clear guide and documentation so that I can help my team’s transition into using the tool smoothly.  
**Task 2:** Create structured GiggleGit documentation   
**Ticket 1:** Create “Getting Started” guide

- Make a step-by-step guide that walks users through the installation process, commands, and GiggleGit’s unique features

**Ticket 2:** Record best practices regarding team cooperation

- Have a section on suggested/recommended workflows for teams using GiggleGit– this may include steps on troubleshooting merges or version conflicts, collaboration tips, etc.

**User Story 3:** As a GiggleGit user, I want a guide for overcoming any recurring problems among all users so that I can troubleshoot more quickly.  
**Task 3:** Create troubleshooting guide for users   
**Ticket 1:** Record frequent issues among users

- Collect feedback from users regarding common problems encountered 

**Ticket 2:** Create troubleshooting guide

- Write step-by-step solutions for all common problems which may include the issue itself and recommended ways to fix it

This is not a user story because although a feature is described, it doesn’t specifically state a goal explaining why that feature is significant for users. Instead, the focus is steered towards the users’ respective experiences.
